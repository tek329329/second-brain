# Life OS — Your second brain

An empty, ready-to-fill second brain. Clone it, start it, and run the `onboard` skill in Claude Code or Codex to build your profile. Nothing personal ships in this repository: your knowledge lives in `vault/`, a separate private Git repository created on first start from `vault-template/` and ignored by this repo.

A portable Markdown knowledge base with a local dashboard, inspired by Nate Herk's four Cs: context, connections, capabilities, and cadence. The primary interface is Claude Code or Codex opened in this folder or in `vault/`; the dashboard is a viewer, history browser, and connector UI.

## Open it
Install Node.js 22.13+ and Git. Install Claude Code or Codex for the assistant.
Open a terminal in this folder:
```
npm ci
npm run build
npm start
```
The first start creates `vault/` from `vault-template/` and commits it. Then mirror the skills so both runtimes see them:
```
npm run skills
```
Open Claude Code (or Codex) in this folder and say "run onboard" to fill in your profile.
Open http://127.0.0.1:4317. On Windows you can double-click Start Life OS.cmd after installing prerequisites.
The server listens on this computer only. Stop it with Ctrl+C in its terminal. For development use npm run dev.

## Begin
1. Click Begin onboarding and answer the seven questions. Answers are saved immediately with Git history.
2. Capture notes, goals, projects, tasks, events, decisions, and meeting transcripts. Use links to associate them.
3. Browse My brain, Knowledge, Calendar, Plans & tasks, and Health & history.
4. Open the project folder in Codex for ongoing work. AGENTS.md routes personal questions to vault/INDEX.md.
5. Ask my brain uses the installed Codex CLI with its configured model and sign-in. It consumes the usual Codex allowance. Advice mode reads files; work mode allows local deliverables. Responses are labeled inference. If CLI authentication is unavailable, run the request in Codex with this project open.

## Files and version history
- Application source: this folder, its own Git repository.
- Knowledge: vault/, a separate Git repository excluded from application Git.
- Records: vault/records/*.md. Metadata is a JSON object between --- delimiters; body is Markdown.
- Source index: vault/INDEX.md, regenerated by npm run index.
- Operating manual: vault/AGENTS.md (Codex) and vault/CLAUDE.md (Claude Code), kept identical. Routing map, capture rules, constraints.
- Wiki, references, connections registry, interview captures: vault/wiki/, vault/references/, vault/connections.md, vault/brainstorms/.
- Skills: canonical in vault/.claude/skills/; npm run skills mirrors them to vault/.agents/skills/, .claude/skills/, and .agents/skills/. Never edit a mirror.
- Credentials and runtime logs: .local/, ignored by Git.
- Local backup bundles: backups/, ignored by Git.
Every successful dashboard record save creates a Git revision. History → select a revision → Restore creates a new revision without deleting previous history. Concurrent edits produce a conflict notice.
Direct edits by Codex or a text editor become visible on Refresh; use Checkpoint after direct edits to regenerate the index and save history.

## Move to another computer
Create a backup with Health & history → Create Git backup, or npm run backup. This verifies the bundle and creates both application and knowledge bundles when the application repository has commits.
Transfer the entire application folder (including hidden .git and vault/.git directories), excluding node_modules, dist, and .local. Alternatively transfer the two verified bundles:
```
git clone application.bundle life-os
cd life-os
git clone knowledge.bundle vault
npm ci
npm run build
npm start
```
Use the actual timestamped bundle filenames. The application bundle includes all application source and its history; the knowledge bundle includes the knowledge and its history. Generated build files and dependencies are rebuilt on the destination.
Sign into Codex and reconfigure app connections on the new computer. Absolute machine paths, credentials, and Codex conversation history are not included.
Backups contain your private knowledge in readable form. Keep them in a private destination.

## Private off-device backup
No remote is created until you choose the host and repository. Set up TWO private repositories, one for application code and one for the knowledge vault, with separate access if desired. Then add the verified URLs as origins:
```
git remote add origin <private-application-repository-url>
git push -u origin main
git -C vault remote add origin <private-knowledge-repository-url>
git -C vault push -u origin main
```
Before changing computers: checkpoint, then push both. On arrival: git pull --ff-only and git -C vault pull --ff-only. If Git reports divergent changes, ask Codex to review and merge them; do not force-push. Avoid editing the same vault on two computers simultaneously.
A local Git bundle is a recovery artifact, not an off-device backup until copied somewhere else.

## Connections
Configure tokens through the local Connections form. Secrets are written only to .local/connections.json, never to browser storage, application Git, exports, or knowledge Git. Limit access to your operating-system account. Re-enter credentials on another computer.
- Google: reads up to 100 upcoming primary calendar events, 25 email metadata/snippets, and 100 Drive file links.
- Microsoft 365: reads up to 100 events, 25 mail summaries, and 100 root Drive links.
- Slack: reads up to 500 messages from one selected channel.
- ClickUp: reads up to five pages of open tasks from one list.
- YouTube: reads channel statistics and up to 25 recent public video metadata items.
- Fathom and Skool: manual export import; direct synchronization is not implemented.
Google and Microsoft adapters accept existing scoped OAuth access tokens; automatic OAuth consent/refresh is not implemented. An expired token shows an error.
All adapters are read-only and manually refreshed. Imported facts are unconfirmed and retain source identifiers. Imports are bounded snapshots, not full account mirrors. Drive imports are links/metadata, not full document content. YouTube transcripts and meeting exports can be imported as text or Markdown.
Connections are not marked successful before a provider response. Live account validation requires your accounts; no connected account data is included in the initial installation.

## Cadence
Routines remain manual by your choice. The Cadence page prepares explicit scheduling requests for Codex if you decide to activate them later. Paste a request into Codex to create an actual recurring automation. The application does not pretend that a saved prompt is a running scheduler. Codex scheduling and machine availability govern execution.
For a local maintenance run, npm run audit saves a deterministic coverage record; the audit skill (run from Claude Code or Codex) is the evidence-based four-Cs audit and saves to vault/audits/. npm run index rebuilds the routing index. npm run skills re-mirrors the skills after editing vault/.claude/skills/.

## Reliability and limitations
- Original source files remain yours. All records are editable and exportable.
- The graph renders real life-area groups and explicit record links; it does not fabricate knowledge nodes.
- The local audit measures coverage and stale records deterministically, not AI intelligence. A confirmed system-purpose goal does not establish your actual biographical profile.
- Wiki synthesis and deep interviews are Codex workflows. Their results require relevant user context and a working Codex session.
- The UI uses plain text for record bodies, so imported HTML cannot execute.
- The application checks request origin, host, and a per-process mutation token. It is designed for loopback access only; do not expose the development server to the internet.
- File imports support .md, .txt, Life OS .json exports, and basic .ics events. Rich PDF/Word/audio extraction should be performed with Codex's document tools, then saved as records.
- JSON imports skip existing IDs to avoid overwriting changes. Full disaster recovery with history uses Git bundles.
- App connections and off-device backup remain pending until configured. Routines are intentionally manual.
